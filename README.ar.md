# إعداد عزل الذكاء الاصطناعي

بيئة معزولة لأدوات برمجة الذكاء الاصطناعي على نظام دبيان ووايلاند. تشمل أدوات سطر الأوامر وتطبيقات سطح المكتب: `Claude Code` و `Copilot CLI` و `Cursor`، وأي أداة تضيفها لاحقا.

- **يُفضَّل التثبيت بصفة الجذر، لكنه ليس إلزاميا.**
  - بصفة الجذر (`su -`): تذهب البرامج إلى `/usr/local`، وتكون مملوكة للجذر، بحيث لا يستطيع أي شيء يعمل باسمك تعديلها.
  - بصفة مستخدم عادي: تذهب البرامج إلى `~/.local`. وهذا يعمل، مع تحذير.
- **ملف الإعدادات يوجد في مجلدك الشخصي.** يسرد الملف `~/.config/ai-sandbox/tools.conf` أدواتك المعزولة. يُنشأ من الإعدادات الافتراضية عند أول استخدام، ويكون خاصا (`600`)، و**لا يظهر أبدا داخل البيئة المعزولة**.
- **إضافة تفاعلية.** يبحث الأمر `ai-sandbox-admin add <name>` في النظام وفي مجلدك الشخصي عن الأداة بالاسم ويطرح بعض الأسئلة.
- **لا يتغير شيء بالنسبة إليك.** يُنقل البرنامج الحقيقي جانبا (`claude` يصبح `.ai-real-claude`) ويحل محله غلاف صغير. سواء كتبت `claude`، أو نقرت على `Cursor` في القائمة، أو استدعى محرر تطوير أو سكربت المسار المطلق: كل المتصلين يحصلون على البيئة المعزولة. لا مجلد `bin` إضافي، ولا حيل في `PATH`.

> **bubblewrap يقرر ما الذي يستطيع الذكاء الاصطناعي رؤيته؛ وإشعار المستخدم في seccomp يقرر ما الذي يستطيع تشغيله.**

| الطبقة | البرنامج | الوظيفة | متى يقرر |
|---|---|---|---|
| الجدران | `bwrap` (bubblewrap) | أي الملفات والعمليات والأجهزة الموجودة للأداة | مرة واحدة، عند البدء |
| الحارس (اختياري) | `aisup` (إشعار المستخدم في `seccomp USER_NOTIF`) | أي البرامج التي يجوز للأداة **تنفيذها**: السماح أو المنع أو سؤالك | عند كل `execve` / `execveat` |

## كيف تبدأ الأداة

```
shell `claude` · IDE · script · menu launcher (Exec=/usr/share/cursor/cursor)
        │
        ▼
~/.local/bin/claude          ← now a 5-line wrapper (made by `sync` / `add`):
        │                       exec /usr/local/bin/ai-sandbox run claude "$@"
        ▼
ai-sandbox run <tool> [args]    reads ~/.config/ai-sandbox/tools.conf
        │
        ▼
[aisup policy] ─► bwrap … ─► ~/.local/bin/.ai-real-claude   (the real program)
```

تثبيت الجذر: `/usr/local/bin/ai-sandbox`. تثبيت المستخدم: `~/.local/bin/ai-sandbox`.

- داخل البيئة المعزولة يعود المسار الأصلي هو البرنامج الحقيقي مرة أخرى، بحيث تستطيع الأداة أن تستدعي نفسها بالاسم.
- **التحديثات:** شغّل البرنامج الحقيقي خارج البيئة المعزولة، مثل `~/.local/bin/.ai-real-claude update`. إذا كتب تحديث برنامجا جديدا فوق الغلاف (مثل `npm install -g` لنسخة أحدث)، فإن خطّاف بدء الصدفة (`ai-sandbox-admin verify -q`، عند كل بدء صدفة) ينقله جانبا ويعيد تغليفه.
- **المجلدات المملوكة للجذر** (مثل `/usr/share/cursor`): يستخدم `sync` / `add` الأمر `sudo`. أما الملف المملوك لحزمة دبيان فيُنقل باستخدام `dpkg-divert`، بحيث يثبّت `apt upgrade` النسخ الجديدة في `.ai-real-<tool>` و**لا يمس الغلاف أبدا**. انظر [التحديثات والحزم والأسرار](#التحديثات-والحزم-والأسرار).
- تمر الوسائط دون تغيير (`claude --resume`، `cursor .`).

## الملفات

هذا المجلد هو المصدر. ينسخ الأمر `install` البرامج منه.

| الملف المصدر | تثبيت الجذر (المُفضَّل) | تثبيت المستخدم | الغرض |
|---|---|---|---|
| `ai-sandbox.sh` | `/usr/local/bin/ai-sandbox` | `~/.local/bin/ai-sandbox` | المشغّل. يقرأ `tools.conf` الخاص بك ويبني أمر `bwrap` (مع `aisup`). |
| `ai-sandbox-admin.sh` | `/usr/local/bin/ai-sandbox-admin` | `~/.local/bin/ai-sandbox-admin` | التثبيت، وإدارة أدواتك. |
| `undo.sh` | `/usr/local/bin/ai-sandbox-undo` (ونسخة في `/var/lib/ai-sandbox/`) | `~/.local/bin/ai-sandbox-undo` (ونسخة في `~/.local/state/ai-sandbox/`) | يعكس التغييرات المسجلة. قائم بذاته. |
| `lib.sh` و `check.sh` و `shell-hook.sh` | `/usr/local/lib/ai-sandbox/` | `~/.local/lib/ai-sandbox/` | محلل الإعدادات، واختبارات الجدران، وخطّاف إعادة التغليف بعد التحديث. |
| `aisup.c` | `/usr/local/lib/ai-sandbox/aisup` | `~/.local/lib/ai-sandbox/aisup` | مشرف تنفيذ `seccomp`. يُبنى إذا توفر `libseccomp-dev` و `cc`. |
| `tools.conf` و `policy.conf` | `/usr/local/lib/ai-sandbox/` | `~/.local/lib/ai-sandbox/` | **الافتراضيات**، تُنسخ إلى إعدادات كل مستخدم عند أول استخدام. |
| `install.sh` / `uninstall.sh` | — | — | اختصاران لـ `ai-sandbox-admin install` / `uninstall`. |
| `Makefile` | — | — | يبني `./aisup` محليا، للتطوير فقط. |

لكل مستخدم، ودائما في مجلده الشخصي:

| المسار | ماذا يكون |
|---|---|
| `~/.config/ai-sandbox/tools.conf` | **أدوات الذكاء الاصطناعي الخاصة بك** وما يجوز لكل منها رؤيته. |
| `~/.config/ai-sandbox/policy.conf` | قواعد تنفيذ `aisup` الخاصة بك. |
| `<dir>/<tool>` (المسار الأصلي، مثل `~/.local/bin/claude`) | الغلاف. |
| `<dir>/.ai-real-<tool>` | البرنامج الحقيقي، المنقول جانبا. يعيده `reset` / `remove` إلى مكانه. |
| `~/.local/state/ai-sandbox/` | سجل الإجراءات والنسخ الاحتياطية ونسخة من `ai-sandbox-undo` (للجذر: `/var/lib/ai-sandbox/`). لا يظهر أبدا داخل البيئة المعزولة. |

**كيف تُحمى إعداداتك:**
- لا يبدأ المشغّل إلا إذا كانت ملفات إعداداتك مملوكة لك وغير قابلة للكتابة من المجموعة أو من الآخرين.
- **يرفض بدء** أي أداة يكون مشروعها أو مسارات `rw` الخاصة بها سبباً في جعل أي من هذه الملفات قابلة للكتابة داخل البيئة المعزولة: ملف الإعدادات، أو غلاف أي أداة، أو برامج تثبيت المستخدم، أو `~/.zshrc` أو `~/.bashrc`.

## التثبيت

**المُفضَّل: بصفة الجذر.**

```sh
su -
apt install bubblewrap                    # مطلوب
apt install libseccomp-dev gcc zenity     # اختياري: aisup ومربع حواره
cd /home/<you>/Workspace/sh-scripts/ai-isolation-setup
bash install.sh
exit
```

تثبيت الجذر:
- ينسخ البرامج والإعدادات الافتراضية إلى `/usr/local`
- يبني `aisup`
- يضيف خطّاف إعادة التغليف إلى `/etc/zsh/zshrc` و `/etc/bash.bashrc`

وهو **لا يمس أي مجلد شخصي**. بعد ذلك يشغّل كل مستخدم هذا الأمر مرة واحدة بصفته نفسه:

```sh
ai-sandbox-admin sync     # ينشئ ~/.config/ai-sandbox/، ويسأل قبل تغليف كل أداة
```

**البديل: بصفة مستخدم عادي** (دون الحاجة إلى الجذر):

```sh
cd ~/Workspace/sh-scripts/ai-isolation-setup
bash install.sh           # → ~/.local، الخطّاف في ~/.zshrc + ~/.bashrc، ويشغّل sync
```

يرفض تثبيت المستخدم العمل إذا كان تثبيت الجذر موجودا أصلا. في هذه الحالة، شغّل `sync` فقط.

> هذا المجلد يوجد داخل `~/Workspace`، الذي يستطيع `Cursor` الكتابة فيه. راجع تغييراته قبل التثبيت، ولا سيما بصفة الجذر.

**بعد ذلك** افتح **نافذة طرفية جديدة** وتحقق:

```sh
head -5 ~/.local/bin/claude   # → "# ai-sandbox wrapper …"
cd ~/Workspace/some-project
ai-sandbox check         # هل كلها PASS؟
claude                   # معزولة
```

## الأوامر

### `ai-sandbox`

| الأمر | ماذا يفعل |
|---|---|
| `ai-sandbox run <tool> [args…]` | يبدأ أداة من `tools.conf` الخاص بك داخل بيئة معزولة. الأغلفة تستدعي هذا الأمر. |
| `ai-sandbox run shell` | ملف اختبار مدمج: صدفة `bash` بالقواعد المشتركة فقط. |
| `ai-sandbox list` | يعرض أدواتك. |
| `ai-sandbox check` | يشغّل اختبارات الجدران من المجلد الحالي. |

| المتغير (لكل تشغيل) | الأثر |
|---|---|
| `AI_PROJECT=/path` | يستخدم مجلد المشروع هذا بدل المجلد الموجود في `tools.conf`. |
| `AISUP=1` | يفرض تشغيل مشرف التنفيذ. |
| `AI_NEW_SESSION=0` | لا يفصل عن الطرفية (انظر `TIOCSTI` أدناه). |
| `AI_DEBUG=1` | يطبع الأمر النهائي قبل تشغيله. |

### `ai-sandbox-admin`

| الأمر | يُشغَّل بصفة | ماذا يفعل |
|---|---|---|
| `install` | الجذر (المُفضَّل) أو المستخدم | يثبّت البرامج (انظر أعلاه). |
| `uninstall` | الجذر: تثبيت النظام؛ المستخدم: تثبيت المستخدم | يزيل البرامج. تثبيت المستخدم يشغّل أيضا `reset` ويسأل قبل حذف `~/.config/ai-sandbox`. قبل إلغاء تثبيت الجذر، على المستخدمين تشغيل `reset`. |
| `search <name>` | أنت | يسرد البرامج ومشغلات القوائم التي يحتوي اسمها على `<name>`. لا يغيّر شيئا. |
| `add [name]` | أنت | إضافة تفاعلية (انظر أدناه). |
| `remove <name>` | أنت | يعيد البرنامج الحقيقي (ويزيل تحويل `dpkg`)، ثم يحذف قسم الأداة. يُسجَّل، بحيث يعيده `ai-sandbox-undo last`. تُحفظ بيانات الأداة. |
| `list` | أنت | يعرض أدواتك. |
| `sync` | أنت | يغلّف كل أداة في `tools.conf` (يسأل قبل أول نقل؛ `sudo` للمجلدات المملوكة للجذر). شغّله بعد التعديل اليدوي. |
| `verify [-q]` | أنت | يعيد تغليف الأدوات التي استبدلها تحديث، ويوجه أدوات `exec-newest` إلى أحدث نسخة، ويحذّر من الأغلفة اليتيمة (البرنامج الحقيقي غير موجود). `-q` (خطّاف الصدفة): صامت إلا إذا كان هناك ما يحتاجك، ولا يستخدم `sudo` أبدا. |
| `reset` | أنت | يعيد كل البرامج الحقيقية. تُحفظ الإعدادات. |

ترفض الأوامر `search` و `add` و `remove` و `sync` و `reset` العمل بصفة الجذر، لأن الإعدادات تخص كل مستخدم.

### ماذا يسأل `add`

1. **أي برنامج.** يبحث في `/usr/bin` و `/usr/sbin` و `/usr/local/bin` و `/usr/games` و `/opt` و `/usr/share` و `/usr/lib` و `/snap/bin`، إضافة إلى `~/.local/bin` و `~/.local/share` و `~/Applications` و `~/bin` ومجلدات `bin` الخاصة بـ `npm` و `bun` و `cargo` و `deno`. تختار نتيجة واحدة أو أكثر بالرقم (`4`، أو `4 3` / `4,3`)، أو تكتب مسارا واحدا أو أكثر. **الأول هو البرنامج الرئيسي.** اختر عدة برامج عندما يكون لأداة واحدة عدة برامج، مثل سكربت سطر الأوامر الخاص بـ `Devin` `/usr/share/devin-desktop/bin/devin-desktop` وثنائية التطبيق `/usr/share/devin-desktop/devin-desktop`: كل واحد يحصل على غلافه الخاص وكلها تعمل في نفس القسم `[section]`. إذا اخترت رابطا رمزيا وهدفه أيضا (`/usr/bin/devin-desktop` يشير إلى `…/bin/devin-desktop`)، يُغلَّف الهدف فقط: الرابط الرمزي يقود أصلا إلى ذلك الغلاف. لا تُدرج ملفات `.desktop` بوصفها برامج.
2. **اسم الملف الشخصي** (قسمة `[section]`)، إضافة إلى **النوع**: `cli` أو `gui`. يخمّن `gui` إذا طابق مشغّل قائمة أو كان التطبيق `Electron`.
3. **مجلد المشروع:** `cwd` لأدوات سطر الأوامر، و `~/Workspace` لتطبيقات الواجهة افتراضيا.
4. **إدخالاتك التي يحتوي اسمها على مصطلح البحث.** يبحث مباشرة داخل `~` و `~/.config` و `~/.local/share` و `~/.cache`. لكل مجلد: قراءة وكتابة، أو قراءة فقط، أو تخطٍ. ولكل ملف: قراءة وكتابة أو تخطٍ.
5. **النقل.** بادئة البرنامج الحقيقي (الافتراضية `.ai-real-`)، ثم تأكيد: `<path>` يصبح `<dir>/.ai-real-<name>`، والغلاف في `<path>`، لكل برنامج اخترته. كيف ينقل:
   - ملف **مملوك لحزمة دبيان** يتحول باستخدام `dpkg-divert --rename` (مع `sudo`)، بحيث تذهب ترقيات الحزمة إلى `.ai-real-<name>`؛
   - أي ملف آخر في مجلد لا تستطيع الكتابة فيه ينقل باستخدام `sudo mv`؛
   - ملفاتك الخاصة تنقل باستخدام `mv` العادي.
5ب. **مجلد البرنامج (تثبيتات المجلد الشخصي فقط).** إذا كان البرنامج في مجلدك الشخصي، يعرض الوصول للقراءة فقط إلى مجلده. بالنسبة إلى حزمة `npm` يعرض مجلد الحزمة كاملا (`…/node_modules/<pkg>`). إذا كان البرنامج رابطا رمزيا إلى مجلد `versions/` (على طريقة `Claude Code`: `~/.local/bin/claude` يشير إلى `~/.local/share/claude/versions/<ver>`)، أو كان موجودا في واحد، فإنه يضيف أيضا `exec-newest = <ذلك المجلد>/*`.
6. **وسائط ومتغيرات بيئة إضافية لتمريرها.** مشغلات القوائم لا تحتاج شيئا: فهي تبدأ المسار الأصلي، الذي أصبح الآن الغلاف. بالنسبة إلى تطبيقات `Electron` الوسائط المقترحة هي `--ozone-platform=wayland --password-store=basic`.
7. **aisup:** نعم أو لا. بالنسبة إلى تطبيق واجهة خارج مجلدك الشخصي، يُضاف تلقائيا `exec-allow = <app dir>/*`.
8. **الحفظ.** يعرض القسم الجديد `[section]` ويشغّل نفس الفحوصات التي يشغّلها المشغّل (بحيث يُرفض قسم يرى بيانات أداة أخرى قبل حفظ أي شيء). إذا أكدت، يضيف القسم إلى `tools.conf` الخاص بك وينفّذ النقل (أو النقلات).

## `tools.conf`

```ini
[claude]                          # اسم الملف الشخصي: الغلاف يشغّل `ai-sandbox run claude`
wrapped = ~/.local/bin/claude     # المسار الأصلي يصبح الغلاف
exec = ~/.local/bin/.ai-real-claude   # مكان نقل البرنامج الحقيقي (مطلق أو ~/…)
type = cli                        # cli | gui
project = cwd                     # cwd | /dir   (منطقة العمل للقراءة والكتابة)
rw = ~/.claude                    # مجلد للقراءة والكتابة، يُنشأ إذا لم يكن موجودا   (قابل للتكرار)
rw-file = ~/.claude.json          # ملف للقراءة والكتابة، يُنشأ إذا لم يكن موجودا  (قابل للتكرار)
ro = ~/.local/share/claude        # مجلد للقراءة فقط، يُتخطى إذا لم يكن موجودا    (قابل للتكرار)
args = --flag                     # يُمرر دائما إلى البرنامج
env-set = DISABLE_AUTOUPDATER=1   # يُضبط في الداخل                            (قابل للتكرار)
env-pass = ANTHROPIC_API_KEY      # يُنسخ من بيئتك
exec-allow = /usr/share/x/*       # قاعدة سماح إضافية في aisup                (قابل للتكرار)
exec-newest = ~/.local/share/claude/versions/*   # يشغّل أحدث نسخة موجودة هناك
aisup = no                        # نعم = يعمل تحت مشرف التنفيذ
```

- `#` تبدأ تعليقا في أي مكان من السطر.
- `shell` اسم محجوز.
- القسم الذي لا يحتوي على `wrapped =` يتخطاه `sync` مع تحذير (لن يبدأ شيء معزولا).
- **عدة برامج في أداة واحدة:** كرّر `exec =` + `wrapped =` أزواجا، بالترتيب (الزوج `exec` رقم N هو البرنامج الحقيقي خلف الغلاف `wrapped` رقم N). الزوج الأول هو البرنامج الرئيسي؛ و `exec-newest` ينطبق عليه فقط. يجب أن تتطابق الأعداد، وإلا يُرفض القسم.

  ```ini
  [devin]
  exec = /usr/share/devin-desktop/.ai-real-devin-desktop        # الرئيسي: ثنائية التطبيق
  wrapped = /usr/share/devin-desktop/devin-desktop
  exec = /usr/share/devin-desktop/bin/.ai-real-devin-desktop    # سكربت سطر الأوامر الخاص به
  wrapped = /usr/share/devin-desktop/bin/devin-desktop
  ```

  غلاف البرنامج الإضافي يشغّل `ai-sandbox run --via <مساره> <tool>`، والمشغّل يقبل فقط مسار `--via` المدرج في ذلك القسم. داخل البيئة المعزولة يكون كل مسار `wrapped` هو برنامجه الحقيقي مرة أخرى، بحيث تستطيع البرامج استدعاء بعضها بعضا (سكربت سطر الأوامر يشغّل ثنائية التطبيق، وليس بيئة معزولة ثانية). تتعامل الأوامر `sync` و `verify` و `remove` و `reset` مع كل زوج.
- `desktop =` (التصميم القديم) يُتجاهل.

| `cursor` | `/usr/share/cursor/cursor` | `~/.config/Cursor` و `~/.cursor` والمشروع `~/Workspace` | — | واجهة؛ `Wayland`، دون سلسلة مفاتيح؛ مجلد مملوك للجذر، يستخدم `sync` الأمر `sudo` |

## التحديثات والحزم والأسرار

- **الأدوات التي تُحدّث في مجلد `versions/`** (`Claude Code`). جُرّبت مع المحدّث الحقيقي (من `2.1.311` إلى `2.1.325`): يرى أن `~/.local/bin/claude` ليس رابطه الرمزي، فيطبع *"التحديث التلقائي يتركه دون مساس"*، ويضيف فقط النسخة الجديدة تحت `versions/`. يبقى الغلاف مطابقا بايتاً بايتاً، حتى عند إعادة تشغيل المثبّت الرسمي.
  - **النسخ القديمة تتراكم.** بسبب الغلاف، يقول المحدّث إنه *"لا يستطيع معرفة أي نسخة يحتاجها مشغّلك، لذلك يحتفظ بها كلها"*. احذف مجلدات النسخ القديمة في `~/.local/share/claude/versions/` بنفسك من حين لآخر؛ فـ `exec-newest` يشغّل دائما الأعلى.
  - **هذا ما تفعله تلك النسخ، وليس وعدا.** يمكن لـ `Anthropic` تغيير المحدّث. يثبّت `../vm-test` النسخة المستقرة *اليوم* والأحدث في كل تشغيل، لذلك أعد تشغيل `tests/run-all.sh 00 60 97` بعد تحديث كبير لـ `Claude`. إذا قام محدّث مستقبلي بالكتابة فوق الغلاف، فإن البديل ما يزال يعمل (جُرّب في `global-test.sh` رقم 6): `verify` (في كل طرفية جديدة) يرى أن الغلاف اختفى ويغلّف البرنامج الجديد مرة أخرى. وفي هذه الأثناء، يشغّل `claude` من طرفية **مفتوحة أصلا** دون عزل. تحقق باستخدام `ai-sandbox-admin verify`.
- **`exec-newest = GLOB`** يعالج ذلك: عند كل بدء يشغّل المشغّل **أعلى نسخة** من بين الملفات القابلة للتنفيذ المطابقة لـ `GLOB`، مقارنة باستخدام `sort -V` (بحيث `1.10` أكبر من `1.9`؛ الأسماء، وليس أوقات الملفات). يبقى `.ai-real-<tool>` **رابطا رمزيا**؛ ويعيد خطّاف الصدفة (طرفية جديدة) توجيهه إلى تلك النسخة الأحدث، بحيث يستخدم تشغيل `.ai-real-<tool>` مباشرة و `undo` الأحدث أيضا. إذا كان `tools.conf` الخاص بك أقدم من هذا، أضف `exec-newest = ~/.local/share/claude/versions/*` تحت `[claude]`.
- **الملفات المملوكة لحزمة دبيان** (مثل `Cursor` في `/usr/share/cursor`) تُنقل باستخدام `dpkg-divert --rename`، وليس `mv`. جُرّبت مع مستودع `apt` حقيقي: يثبّت `apt upgrade` و `apt install --reinstall` النسخة الجديدة في `.ai-real-<tool>`، ويبقى الغلاف مطابقا بايتاً بايتاً ويبقى `dpkg -V` نظيفا. تزيل الأوامر `reset` و `remove` و `undo` التحويل مرة أخرى.
  - **إزالة `apt remove` لحزمة مغلفة** تحذف البرنامج الحقيقي لكنها لا تحذف غلافنا (فـ `dpkg` لا يعرفه). يصبح الغلاف عندها يتيما: تشغيله يقول *"حُذفت حزمة دبيان الخاصة به على الأرجح؛ نظّف باستخدام: ai-sandbox-admin remove <tool>"*، وتحذّر الطرفية الجديدة بالشيء نفسه. شغّل ذلك الأمر.
- **أدوات `npm` في مجلدك الشخصي:** يمنح `add` الوصول للقراءة فقط إلى مجلد الحزمة كاملا (`…/node_modules/<pkg>`)، وليس إلى `bin/` فقط.
- **الأسرار المعروفة لا تُكشف أبدا**، مهما قال `tools.conf`. لا يجوز لأي `project` أو `rw` أو `ro` أن يكون، أو يحتوي، أو يوجد داخل واحد منها. تُحل الروابط الرمزية أولا. تغطي القائمة المدمجة:
  - المفاتيح وبيانات الاعتماد: `~/.ssh` و `~/.gnupg` و `~/.password-store` و `~/.pki` و `~/.netrc` و `~/.git-credentials` و `~/.local/share/keyrings` و `1Password` (`~/.config/op`) و `Bitwarden`؛
  - السحابة: `~/.aws` و `~/.azure` و `~/.config/gcloud` و `~/.oci` و `~/.kube` و `~/.docker` و `doctl` و `hcloud` و `~/.terraform.d` و `~/.vault-token` و `rclone`؛
  - رموز المطورين: `~/.config/gh` و `hub` و `glab` و `~/.config/github-copilot` و `~/.npmrc` و `~/.yarnrc.yml` و `~/.pypirc` وبيانات اعتماد `cargo` و `gem`؛
  - المتصفحات والبريد: `~/.mozilla` و `~/.thunderbird` و `Chrome` و `Chromium` و `Brave` و `Edge` و `Vivaldi` و `Opera`، إضافة إلى **كل `~/snap` و `~/.var/app`** (تطبيقات `snap` و `Flatpak`، التي تحفظ ملفات متصفحاتها هناك).
- **القائمة ليست كاملة.** تذكر المواقع المعروفة. الأداة التي تخزّن رمزها في مكان آخر ليست محمية، لذلك أبقِ `rw` / `ro` ضيقة. يستطيع المدير إضافة إدخالات أو إزالتها في **`/etc/ai-sandbox/secrets.conf`** (`deny ~/.config/mytool` / `allow ~/.pki`، واحد في كل سطر). يقرأ المشغّل الملف فقط إذا كان مملوكا للجذر وغير قابل للكتابة من المجموعة أو من الآخرين.
- **بيانات أدوات الذكاء الاصطناعي معزولة لكل أداة. لا يجوز لأي أداة أن ترى مجلد بيانات أداة أخرى.** إذا كان `rw` أو `rw-file` أو `ro` أو `project` لأداة (ثابت، أو المجلد الذي تبدأ فيه أداة `cwd`) هو، أو يحتوي، أو يوجد داخل مسار تسرده أداة أخرى بوصفه `rw` أو `rw-file` أو `ro`، فإنه يُرفض. على سبيل المثال، يُرفض `[claude]` مع `rw = ~/.copilot`. تُحل الروابط الرمزية أولا. يعمل الفحص في المشغّل وفي `ai-sandbox-admin add` / `sync`. بخلاف قائمة الأسرار، لا توجد استثناءات: لا يستطيع `/etc/ai-sandbox/secrets.conf` السماح به. بيانات المحرر مثل `~/.config/Code` محمية بهذه الطريقة، وليس بقائمة الأسرار: امنح المحرر إدخاله الخاص (`[code]` مع `rw = ~/.config/Code`) ولا تستطيع أي أداة أخرى الحصول عليه. **دون مثل هذا الإدخال لا يوجد شيء يحمي `~/.config/Code`**، ويمكن أن يحتوي على رموز (فـ `VS Code` الذي بدأ مع `--password-store=basic` يحفظها هناك في ملف سهل فك تشفيره).
- **القائمة تحميك فقط في تثبيت الجذر.** توجد في البرنامج. في تثبيت المستخدم يكون البرنامج في `~/.local/bin`، مملوكا لك، لذلك يستطيع أي برنامج يعمل باسمك تعديل القائمة (جُرّب: إزالة `~/.ssh` منها جعلت المفتاح مقروءا).

## ما تحصل عليه كل أداة

| | |
|---|---|
| قراءة فقط | `/usr` (مع روابط `/bin` و `/sbin` و `/lib` و `/lib64` الرمزية) و `/etc` و `~/.gitconfig` و `~/.config/git` ومجلدات `DNS` في `/run` |
| قراءة وكتابة | مجلد المشروع (وإدخالات `rw` / `rw-file` الخاصة بالأداة) |
| جديد / خاص | `/proc` و `/dev` و `/dev/shm` و `/tmp`؛ **`$HOME` هو `tmpfs` فارغ** |
| مساحات الأسماء | كلها غير مشتركة **عدا الشبكة**؛ `--die-with-parent` (عدا سطر أوامر تطبيق واجهة، أدناه) و `--cap-drop ALL` و `no_new_privs` (لا يعمل `sudo` / `setuid`) |
| البيئة | تُمسح، ثم يبقى فقط `HOME USER LOGNAME PATH SHELL TERM COLORTERM LANG LANGUAGE LC_ALL EDITOR VISUAL` (مع `env-set` / `env-pass`) |
| الجلسة | `--new-session` (يمنع `TIOCSTI`) ما لم يكن `AI_NEW_SESSION=0` |

يرفض المشغّل استخدام `/` أو `/home` أو `/usr` أو `/etc` أو `/tmp` أو `$HOME` بوصفها مجلد مشروع. عند البدء من مجلد فرعي للمشروع، تبدأ الأداة في ذلك المجلد الفرعي.

**أدوات الواجهة تحصل أيضا على:**
- مقبس `Wayland` و `/dev/dri` (وحدة معالجة الرسوميات)، إضافة إلى `/sys` للقراءة فقط.
- مجلد تشغيل مشترك و `/tmp` تحت `$XDG_RUNTIME_DIR/ai-sandbox/<tool>/`. يصل إطلاق ثانٍ، مثل رد اتصال تسجيل دخول المتصفح، إلى النافذة العاملة بهذه الطريقة.
- **لا `X11`** و**لا `D-Bus` أو سلسلة مفاتيح**.
- **سطر أوامر التطبيق نفسه يعمل** (`cursor .` و `cursor file.py` و `cursor --version` و `cursor --install-extension …`). `/usr/bin/cursor` سكربت يشغّل الثنائية المغلفة مع `ELECTRON_RUN_AS_NODE=1` و `cli.js`. يحتفظ المشغّل بذلك المتغير (ويتخطى `args`، وهي أعلام `Electron`). بعد ذلك:
  - النافذة التي يفتحها `cli.js` تستمر في العمل بعد خروج `cli.js`، في نفس البيئة المعزولة. تنتهي تلك البيئة المعزولة عندما تنتهي آخر عملية فيها.
  - تحصل الطرفية على مخرجات `cli.js` ورمز خروجه فورا. يعود `$(cursor --version)` و `cursor . | cat` أيضا.
  - `cursor file` الثاني يذهب إلى النافذة العاملة.
  - النوافذ المفتوحة بهذه الطريقة لا تحصل على `args`. يختار `Electron` `Wayland` بنفسه، ودون سلسلة مفاتيح في الداخل يخزّن الأسرار بالطريقة الأساسية.

**لا يظهر أبدا:** `~/.ssh` و `~/.gnupg` و `~/.aws` وملفات المتصفحات وسجل الصدفة ورموز الأدوات الأخرى و `SSH_AUTH_SOCK` و**إعدادات البيئة المعزولة**. لذلك يجب تنفيذ `git push` و `ssh` خارج البيئة المعزولة.

## مشرف التنفيذ (aisup)

يُشغَّل لكل أداة مع `aisup = yes`، أو لتشغيل واحد مع `AISUP=1`. إذا كان مطلوبا لكنه غير مبني، ترفض الأداة البدء.

```
ai-sandbox ─► aisup (outside the sandbox, supervisor)
               └─ fork ─► no_new_privs + seccomp filter ─► exec bwrap ─► tool ─► children
                              execve/execveat ── paused ──► rules
                                                            allow → runs
                                                            deny  → EPERM
                                                            ask   → zenity dialog (60 s → deny)
```

- **قواعد التشغيل.** يضع المشغّل `allow <bwrap> *` و `allow <tool's exec>*` وسطور `exec-allow` الخاصة بالأداة أولا، ثم يضيف `~/.config/ai-sandbox/policy.conf`.
- **المطابقة.** كل سطر هو `allow|deny|ask <glob>`، يُطابق مع `"/abs/path arg1 arg2 …"`. أول مطابقة تفوز، وينطبق `default <action>` في النهاية. `*` تطابق `/` أيضا.
- **الملف الافتراضي `policy.conf`:**
  - يسمح بـ `/proc/self/exe` (مساعدو `Electron`) وبرامج النظام العادية.
  - يمنع `sudo` و `su` و `pkexec`.
  - يسأل عن أدوات الشبكة و `rm -r…` و `git push` و `npm publish` و `python3 -c` و `perl -e`.
  - `default ask`.
- **البرامج غير الموجودة.** تنفيذ مسار غير موجود يفشل مع `ENOENT`، دون موجه أو إدخال في السجل.
- **السجل.** تذهب القرارات إلى `~/.local/state/aisup.log` (أو `$AISUP_LOG`). الإدخالات الصغيرة أتت من السياسة؛ والإدخالات الكبيرة أتت منك.
- **TIOCSTI.** يمنعه المرشح، لذلك `AISUP=1 AI_NEW_SESSION=0` آمن.
- **يفشل مغلقا.** إذا مات `aisup`، تحصل البيئة المعزولة على `SIGKILL` وتفشل التنفيذات المعلقة مع `ENOSYS`.
- **TOCTOU.** يُتحقق من معرّف الإشعار باستخدام `SECCOMP_IOCTL_NOTIF_ID_VALID` بعد قراءة الوسائط ومرة أخرى بعد مربع الحوار.
- **مربع حوار واحد في كل مرة.**

## الحدود

- **تثبيت الجذر مقابل تثبيت المستخدم:**
  - تثبيت الجذر يجعل *البرامج* غير قابلة للتلاعب.
  - إعداداتك في مجلدك الشخصي في الحالتين. وهي آمنة من الذكاء الاصطناعي (غير مرئية داخل البيئة المعزولة)، لكنها ليست آمنة من البرامج الأخرى التي تعمل باسمك خارجها.
  - تثبيت المستخدم يجعل البرامج قابلة للتعديل مثل الإعدادات، بما فيها قائمة الأسرار المدمجة.
- **التجاوز ما يزال ممكنا عن قصد.** تشغيل `.ai-real-<tool>` مباشرة غير معزول، والأداة التي تضم نسختها الخاصة في مكان آخر (مثل امتداد محرر تطوير يشحن `claude` الخاص به) تحتاج إلى إدخال خاص بها.
- **قواعد التنفيذ حاجز إرشادي.**
  - `python3 -c …` تنفيذ واحد، لذلك يُفحص المفسر فقط.
  - خيط آخر يمكنه إعادة كتابة المسار بعد أن يقرأه `aisup` (سباق `TOCTOU`).
  - الجدار الصلب هو تركيبات `bwrap`.
- **الشبكة غير مفلترة.** هذا هو أكبر ثغرة مفتوحة: ترى الأداة مشروعها فقط، لكنها تستطيع إرسال ذلك المشروع إلى أي مكان. انظر [غير المنفذ بعد](#غير-المنفذ-بعد).
- **غير مغطى:**
  - عزل تطبيقات `Flatpak` و `Snap` نفسها.
  - المشغلات التي يبدأ `Exec=` فيها بـ `env …`.
- **مُختبر في أجهزة افتراضية، وليس على آلات كثيرة.**
  - **أدوات سطر الأوامر:** يشغّل `../vm-test/` المجموعة الكاملة على جهاز افتراضي جديد `Debian 12` مع `Claude Code` الحقيقي و `Codex CLI` (التثبيت والتحديثات الحقيقية و `apt upgrade` الحقيقي والتراجع). كل الفحوصات تنجح؛ وتُبلغ الشبكة المفتوحة وضعف الإعدادات أعلاه بوصفهما تحذيرين.
  - **Cursor الحقيقي و Wayland:** جهاز افتراضي ثانٍ (`vagrant up gui`) يشغّل `Cursor` الحقيقي من مستودعه الرسمي `apt` على `sway`. جُرّب: البدء من القائمة ومن `cursor .`؛ كل عمليات `Cursor` معزولة؛ لا يستطيع رؤية `~/.ssh` وأصدقائه؛ بيئة `Chromium` المعزولة نفسها ما تزال تعمل في الداخل (دون `--no-sandbox`)؛ `apt --reinstall` والترقية يحافظان على الغلاف؛ `remove` يتراجع عنه.
  - **Cursor، غير المُختبر:** تسجيل الدخول والطرفية المدمجة وبيئة `Cursor` المعزولة نفسها. بيئته المعزولة هي مساعد `cursorsandbox`؛ وهو يريد `AppArmor` والقدرات، التي لا يملكها شيء داخل `bwrap`، لذلك توقع أن تكون غير متاحة. `bwrap` هو الجدار في كل الأحوال. الثلاثة تحتاج إلى حساب حقيقي ونقرات؛ ويحتوي `../vm-test/README.md` على الخطوات اليدوية.

## استكشاف الأخطاء

| العرض | الإصلاح |
|---|---|
| `claude` ما يزال غير معزول | شغّل `ai-sandbox-admin sync` وأجب `y`. يجب أن يظهر `head -2 ~/.local/bin/claude` العبارة `# ai-sandbox wrapper`. |
| `… must belong to you and not be group/world-writable` | `chmod 600 ~/.config/ai-sandbox/*.conf` |
| `… would be writable inside and contains …` | مسار `rw` / `project` يغطي ملفات البيئة المعزولة نفسها. استخدم مسارا أضيق. |
| `refusing to expose '…'` | انتقل إلى مجلد مشروع أولا، أو عيّن `AI_PROJECT=`. |
| `run this as your normal user` | الأوامر `search` و `add` و `remove` و `sync` و `reset` تدير إعداداتك. اخرج من صدفة الجذر أولا. |
| `root already installed it system-wide` | لا حاجة إلى تثبيت مستخدم. شغّل فقط `ai-sandbox-admin sync`. |

| Cursor: *SUID sandbox helper … not configured* | غير مطلوب على `Debian 12`: بيئة `Chromium` المعزولة تعمل داخل `bwrap` (مُختبر). إذا منعته نواتك مع ذلك، أضف `--no-sandbox` إلى `args` في `[cursor]` وشغّل `sync`؛ فـ `bwrap` ما يزال الجدار. |
| `cursor .` يفتح `cli.js` كملف | تثبيت `ai-sandbox` لديك أقدم من إصلاح سطر أوامر `Electron`. أعد تشغيل التثبيت. |
| Cursor لا يظهر نافذة | `AI_DEBUG=1 ai-sandbox run cursor` في طرفية واقرأ الأخطاء. |
| Claude: لم تُحفظ الإعدادات | استبدل `rw-file = ~/.claude.json` بـ `env-set = CLAUDE_CONFIG_DIR=~/.claude`. |
| Copilot يطلب تسجيل الدخول في كل مرة | لا توجد سلسلة مفاتيح في الداخل. صدّر `GH_TOKEN` قبل بدئه. |
| كثرة موجهات `aisup` | اقرأ `~/.local/state/aisup.log` وأضف سطور `allow` فوق `default ask` في `policy.conf` الخاص بك. |
| سطر الأوامر لا يعيد الرسم عند تغيير الحجم | استخدم `AISUP=1 AI_NEW_SESSION=0`. |
| `make`: `missing separator` | يجب أن تبدأ سطور الوصفات في `Makefile` بعلامة جدولة `TAB`. |

## السجل والتراجع

يُسجَّل كل تغيير على القرص بواسطة `ai-sandbox-admin` (التثبيت و `sync` و `add` و `remove` و `reset` وإلغاء التثبيت وإعادة التغليف من خطّاف الصدفة) وبواسطة `ai-sandbox` (المجلدات والملفات التي ينشئها لأداة). ويُنسخ كل ما يُستبدل أو يُحذف إلى `backups/` أولا.

| من | السجل | النسخ الاحتياطية |
|---|---|---|
| الجذر | `/var/lib/ai-sandbox/actions.log` | `/var/lib/ai-sandbox/backups/` |
| أنت | `~/.local/state/ai-sandbox/actions.log` | `~/.local/state/ai-sandbox/backups/` |

الأمر الذي لا يغيّر شيئا لا يكتب شيئا. التغييرات التي أُجريت مع `sudo` (مثل تغليف `Cursor`) تكون في سجلك، معلّمة `sudo`، وتراجعها يستخدم `sudo` أيضا.

```sh
ai-sandbox-undo list            # التشغيلات التي ما يزال يمكن التراجع عنها، الأحدث أولا
ai-sandbox-undo show last       # ماذا غيّر أحدث تشغيل
ai-sandbox-undo -n last         # تجربة جافة
ai-sandbox-undo last            # التراجع عن أحدث تشغيل (يسأل أولا؛ -y = لا يسأل)
ai-sandbox-undo run <RUN-ID>    # التراجع عن تشغيل واحد
ai-sandbox-undo all             # التراجع عن كل شيء والعودة إلى ما قبل التثبيت
ai-sandbox-undo purge           # الخطوة الأخيرة جدا، بعد `all`: حذف السجل والنسخ الاحتياطية
                                # وهذه الأداة و aisup.log والمجلدات الفارغة التي أنشأها
ai-sandbox-undo prune [DAYS]    # توفير مساحة: إسقاط النسخ الاحتياطية للتشغيلات المتراجع عنها (والأقدم من DAYS)
```

- **يمكنه التوقف في أي مكان.** يُسجَّل كل تغيير *قبل* إجرائه، لذلك لا يترك `Ctrl-C` أو العطل أو انقطاع التيار أو الأمر الفاشل أبدا تغييرا لا يعرفه السجل. يتعرف التراجع على التغييرات المسجلة التي لم تحدث ويتخطاها بهدوء. التراجع الذي توقف في المنتصف يستمر من حيث توقف عند تشغيله مرة أخرى. يقتل `../vm-test` (الاختبار 98) التثبيت و `sync` وإلغاء التثبيت والتراجع باستخدام `SIGKILL` عند **كل خطوة**، لتثبيت مستخدم وتثبيت جذر وتحويل `dpkg-divert` لملف حزمة. وفي كل مرة، يعيد `undo all` + `purge` المجلد الشخصي والنظام **بايتاً بايتاً** كما كانا من قبل، ما عدا بيانات الأداة والنسخ الأحدث المدرجة تحت *ما يبقى* أدناه.
- **أي تراجع تشغّل.** أول شيء يفعله `install` هو وضع أداة التراجع بجانب السجل، بحيث يمكن التراجع حتى عن تثبيت توقف عند خطوته الأولى باستخدام `~/.local/state/ai-sandbox/ai-sandbox-undo all` (للجذر: `/var/lib/ai-sandbox/ai-sandbox-undo all`).
- **ملفات صدفة `rc`** (`~/.bashrc` و `~/.zshrc` و `/etc/bash.bashrc` و `/etc/zsh/zshrc`): يزيل التراجع بالضبط السطرين اللذين أضافهما التثبيت. تعديلاتك اللاحقة تبقى. سطر الخطّاف المتبقي غير ضار على أي حال: فهو يعمل فقط إذا كان سكربته موجودا.
- **آمن افتراضيا.** قبل عكس تغيير، يتحقق من أن الشيء ما يزال يبدو كما يقول السجل. يقارن الفحص المحتوى (تجزئة `sha256`)، وليس وقت التعديل: إعادة كتابة نفس المحتوى لا تُعد تغييرا. إذا غيّرته أنت أو تحديث منذ ذلك الحين (مثل تعديل `tools.conf` يدويا)، تُتخطى تلك الخطوة ويُبلغ عنها. يجبر `-f` عليها، بعد حفظ النسخة الحالية في `backups/forced-*`.
- **المجلدات غير الفارغة لا تُحذف أبدا**، حتى مع `-f` (مثل `~/.claude` بعد أن حفظت الأداة بيانات فيه).
- **التراجع عن التثبيت أو عن إلغاء التثبيت** يزيل أو يستعيد `ai-sandbox-undo` نفسه. لهذه الحالة، استخدم النسخة بجانب السجل، التي تبقى دائما: `~/.local/state/ai-sandbox/ai-sandbox-undo` (للجذر: `/var/lib/ai-sandbox/ai-sandbox-undo`).
- **إعادة التغليف بعد تحديث** تُسجَّل ملاحظات، وليست تغييرات: التراجع عن التثبيت يترك *أحدث* نسخة من الأداة في مكانها. النسخة القديمة المتقادمة تُسقط، ولا يُحتفظ بها احتياطيا.
- **النسخ الاحتياطية** تحتوي على كل ملف استبدله الإعداد أو حذفه. شغّل `prune 30` من حين لآخر.

## إلغاء التثبيت

```sh
ai-sandbox-admin reset          # كل مستخدم: يعيد البرامج الحقيقية (تُحفظ الإعدادات)
su -; ai-sandbox-admin uninstall   # تثبيت الجذر
ai-sandbox-admin uninstall      # أو، لتثبيت المستخدم (يعيد الضبط أيضا؛ ويسأل عن الإعدادات)
```

لا تُمس بيانات الأدوات نفسها (`~/.claude` و `~/.config/Cursor` …) أبدا.

**طريقتان للخروج:**
- **`uninstall`** يزيل البرامج والأغلفة والخطّافات، ويُبقي السجل، بحيث ما يزال يمكنك التراجع عن إلغاء التثبيت.
- **`undo all` ثم `purge`** يعود إلى *بالضبط* الحالة قبل التثبيت، بما فيها السجل نفسه. وهذه هي التي تُستخدم بعد التجربة:

```sh
~/.local/state/ai-sandbox/ai-sandbox-undo all     # تثبيت المستخدم (للجذر: /var/lib/ai-sandbox/ai-sandbox-undo all)
~/.local/state/ai-sandbox/ai-sandbox-undo purge
```

ما يبقى بعد `undo all` + `purge`، عن قصد:
- البيانات التي حفظتها أداة أثناء تشغيلها (`~/.claude/…`)، تماما كما لو كانت تعمل دون البيئة المعزولة؛
- نسخة أداة أحدث ثبّتها محدّث في هذه الأثناء.

## غير المنفذ بعد

- **قائمة سماح الشبكة:** مساحة شبكة خاصة (`pasta`) مع خادم وكيل يسمح فقط بنطاقات واجهة برمجة التطبيقات الخاصة بكل أداة. حتى ذلك الحين، اعتبر كل أداة معزولة قادرة على رفع مشروعها.
